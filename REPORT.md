# PAUK — отчёт

## TL;DR

- В базе **1833 публикации** сотрудников ИТМО за период 2025-01-01 — 2026-05-01.
- **374 PDF** скачано (20.4%), **1369 абстрактов** реконструировано (74.7%),
  у **398 публикаций** (22%) нет ни того ни другого.
- **166 PDF** (9% базы) недоступны из-за anti-bot защиты издателей; смена
  User-Agent на браузерный добавила лишь +5 PDF.
- В материалах **86 публикаций** (4.7%) regex нашёл ссылки на стек хостингов
  кода — суммарно **170 URL-кандидатов**, из них **90% на github.com**.
- LLM (`openai/gpt-4o-mini`) подтвердил **103 из 170 кандидатов как
  авторские** (61%), отклонил 67 как цитаты на чужие инструменты.
- Итог в `publications`: **67 публикаций с `has_code = 1`** (3.7% от всей
  базы, 4.7% от тех у кого был материал для анализа).
- Стоимость прогона LLM на 170 кандидатах - **≈ $0.02**, время - около минуты.

## 1. Архитектура пайплайна

Шесть скриптов в `scripts/`, каждый идемпотентен:

```
OpenAlex
  │
  ├── populate_publications.py ── publications (метаданные)
  │
  ├── fetch_papers.py ─────────── publications.pdf_url
  │     (API-сессия для OpenAlex,  publications.pdf_local_path  (data/pdfs/{id}.pdf)
  │      browser-сессия для PDF)   publications.abstract
  │
  ▼
extract_repo_links.py ─────────── repo_links (url, host, context, page_number)
  │   источники по приоритету:
  │     1) видимый текст PDF
  │     2) гиперссылки PDF (/Annots)
  │     3) абстракт
  ▼
classify_repo_links.py ────────── repo_links.is_relevant
  │   (LLM через OpenRouter)       repo_links.llm_confidence
  │                                repo_links.llm_reason
  ▼
sync_publications.py ──────────── publications.has_code = 1
                                  publications.code_url  = JSON-массив URL
```

API-ключи, email лежат в `.env` и подгружаются `python-dotenv`.
`.env` лежит в `.gitignore`, шаблон - в `.env.example`.

## 3. Схема БД

`data/itmo_research_opensource.db`, 11 МБ. Ключевые поля относительно задачи:

**`publications`** (1833 строки):

| поле | заполняет | смысл |
| --- | --- | --- |
| `id`, `title`, `journal`, `doi`, `year`, `authors`, ... | populate | метаданные OpenAlex |
| `pdf_url` | fetch_papers | прямая ссылка на PDF; `""` = «проверено, OA нет» |
| `pdf_local_path` | fetch_papers | путь до файла в `data/pdfs/` |
| `abstract` | fetch_papers | реконструированный из `abstract_inverted_index`; `""` = «нет» |
| `has_code` | sync_publications | 1 если LLM подтвердил хоть одну ссылку |
| `code_url` | sync_publications | JSON-массив подтверждённых URL |

**`repo_links`** (170 строк после прогона):

| поле | заполняет | смысл |
| --- | --- | --- |
| `publication_id` | extract | FK на `publications.id` |
| `url`, `host` | extract | URL + один из `SUPPORTED_HOSTS` |
| `context` | extract | 200 символов окружения |
| `page_number` | extract | номер страницы; `NULL` если из абстракта |
| `is_relevant` | classify | 1 = репо авторов, 0 = чужое, NULL = не классифицировано |
| `llm_confidence`, `llm_reason` | classify | уверенность и причина вердикта |

Прочие таблицы (`persons_itmo`, `persons_external`, `publication_authors`,
`departments`, `publication_departments`) — наследие исходной задачи о
публикациях, в задаче про код используются только косвенно (имена авторов
в `JOIN` для LLM-промпта).

## 5. Анализ

### 5.1. Почему OA-покрытие именно такое (20%)

Структура издательской привязки ИТМО на нашей выборке:

- **Российские OA-журналы (ntv.elpub.ru, vestnik.dgtu.ru,
  progressive-economy.ru и др.) — около 30% всех скачанных PDF.**
  Эти журналы по умолчанию открытые, без anti-bot, у нас 100% успех.
- **Препринты / OA-серверы (arXiv, ResearchSquare) — ещё 16%.** Тоже
  без проблем.
- **Крупные журналы с OA-опцией (Nature, Springer, Wiley, RSC) — 30%.**
  Скачиваются только статьи, оплаченные авторами как Gold OA; остальные
  за paywall.
- **Платные журналы (MDPI, Elsevier, ACM, IEEE) — заблокированы
  технически.** Это не paywall в смысле «нет права», а активная защита
  от скрейпинга — даже когда PDF формально OA.
- **Конференционные тезисы / локальные сборники — у OpenAlex часто нет
  ни OA-ссылки, ни абстракта.** Это 22% базы.

20% — это потолок для подхода «у нас только publicly accessible PDFs».
Поднять выше можно только институциональным доступом через прокси-сервер
ИТМО или подпиской на сервисы вроде Unpaywall + интеграцией Sci-Hub
(юридически серая зона).

### 5.2. Anti-bot барьер

**MDPI один даёт 55% всех упавших PDF** (91 из 166). Их защита — это
Cloudflare и JS-challenge. На простой смене User-Agent они не ловятся.

Реалистичные способы обхода (в порядке возрастания сложности и
неоднозначности):
1. **Unpaywall API** — он часто знает альтернативную локацию (зеркало в
   институциональном репозитории, версия на arXiv).
2. **Playwright или Selenium** — рендерит JS, проходит Cloudflare. Тяжело,
   медленно, требует браузер на каждый PDF.
3. **Платные сервисы (ScrapingBee, Bright Data)** — обходят anti-bot за
   деньги ($0.001 за запрос).

На этой задаче я остановился на варианте «зафиксировать как известное
ограничение». 9% базы — не та цифра, ради которой стоит закапываться в
JS-рендеринг.

### 5.3. Абстракт и аннотации не для красоты

На малой выборке (50 публикаций) и абстракт, и `/Annots` дали 0
кандидатов — это могло создать впечатление, что они бесполезны. **На
полной выборке оба источника работают:**

- абстракт дал 58 кандидатов (34% от всех);
- аннотации PDF дали 27 кандидатов (16%).

Без этих источников мы бы потеряли половину кандидатов. То есть
архитектура «парсим всё, что есть» оправдана статистически.

Любопытный частный случай — абстракт даёт URL даже у публикаций, у
которых нет OA PDF. Эти 58 ссылок — единственный шанс что-то найти у 50%
базы.

### 5.4. LLM качество и поведение по хостам

Главное наблюдение — **резко разная precision по хостам**:

| host | precision (доля ДА от всех кандидатов) |
| --- | --- |
| github.com | **66.7%** |
| huggingface.co | **7.7%** |

GitHub-ссылки в научной статье в **двух из трёх** случаев — действительно
выложенный авторами код. Это следствие культуры: когда исследователь
кладёт код на GitHub и упоминает его в статье, он обычно пишет «our code
is available at github.com/X/Y», и LLM такие случаи уверенно ловит.

HuggingFace ссылки наоборот — почти всегда **чужие модели**: PyTorch
embedding, Llama, BERT, и т.п. HF в современных публикациях фактически
выполняет роль «package index для моделей», поэтому ссылка на него почти
всегда указывает на чужой инструмент. Это **не баг LLM**, а отражение
реального устройства экосистемы.

Что это даёт практически:
- если делать ещё одну итерацию точности — GitHub-enrichment даст
  непропорционально большой выигрыш, потому что 90% кандидатов это
  github;
- если хочется отдельно собирать «модели/датасеты к статье» — для них
  лучше отдельный пайплайн с другими правилами, не пытаться смешивать
  с поиском кода.

### 5.5. Курьёз: публикация-репозиторий

Лидер по числу подтверждённых ссылок — **W7117745988 / `Digiratory/FluctuationAnalysisTools 1.10.0`** с 24 подтверждёнными URL. Это
не статья в обычном смысле, а **GitHub-релиз библиотеки**, у которого
есть DOI через Zenodo. OpenAlex проиндексировал этот релиз как «работу
ИТМО», в его «тексте» (README + release notes) — куча ссылок на
другие репозитории и инструменты, и LLM пометил их все как авторские
(потому что в контексте действительно стоят формулировки «our tool»).

Это **известное искажение** OpenAlex — он смешивает разные типы works:
статьи, релизы, датасеты, тезисы. Фильтра по `type` в нашей БД сейчас
нет; если потом захочется, можно сохранять `OpenAlex.type` в
`publications` и фильтровать `WHERE type = 'article'`. На общую
статистику этот единичный edge-case не сильно влияет, но он завышает
число подтверждённых ссылок на 24 строки.

### 5.6. Реальная находимость кода у ИТМО

Получили **67 публикаций из 1833 с подтверждённым кодом** = **3.7%
базы**. Если убрать один edge-case с релизом и одну-две границы
LLM-ошибок — **3.4–3.6%** твёрдых случаев. Это **нижняя оценка**.

Декомпозиция:

| ограничение | оценка влияния |
| --- | --- |
| фундаментальный OA-потолок (20% PDF) | главный фактор |
| anti-bot блок MDPI и др. (9% потенциально OA) | минус 100-130 публикаций материала |
| LLM-ошибки (precision не 100%) | вторичный фактор |
| 22% публикаций без любого материала в OpenAlex | минус 400 публикаций материала |

То есть подавляющий вклад — **доступность материала**, а не качество
алгоритма. У 1435 публикаций мы имеем хоть какой-то текст, из них
**4.7% содержат подтверждённый авторский код**. На большой картине это
говорит, что среди реально проверяемых работ ИТМО **5% сопровождаются
открытым кодом** — это правдоподобная цифра для научной организации
смешанного профиля (физика + биология + ИТ + социальные науки).
