# `pauk/paper_graph/` — граф одной статьи

**Что здесь:** откуда берётся разбор статьи на разделы, утверждения
(claims) и файлы репозитория, в каком виде он лежит на диске и как
попадает в карту.

**Какие файлы задействует:** `pauk/paper_graph/osa_export.py`,
`pauk/models/paper_graph.py`, `pauk/gui/generate_paper_graphs.py`,
`pauk/gui/web/paper-graph.js`.

Остальной PAUK работает на уровне публикации целиком: `Publication`
`-[:MENTIONS_LINK]->` `Repository`, ссылка на код привязана к странице PDF
и куску окружающего текста ([pipeline/code-links.md](pipeline/code-links.md)).
Граф статьи — уровень внутри публикации:

```
Publication
  └── Section           раздел статьи (Метод, Эксперименты, …)
        └── Claim       проверяемое утверждение, извлечённое из этого раздела
              ├── File    файл репозитория, в котором оно реализовано
              └── Source  откуда в статье утверждение взято
```

**В Neo4j этого нет.** Данные читаются с диска и живут только в файле
карты — узлов и связей под них в графе не заведено (см.
[neo4j-graph.md](neo4j-graph.md)).

## Откуда данные

Из [OSA](https://github.com/ITMO-NSS-team/Open-Source-Advisor), не из
пайплайна PAUK. Ничего здесь не вызывает OSA и не ходит в модель — читаются
артефакты уже завершённого прогона:

- `osa_tool/operations/analysis/paper_claims/` — PDF → Marker Markdown →
  разделы → claims (`claim`, `original_text`, `category`, `verifiability`,
  `section_name`);
- `osa_tool/operations/analysis/repository_validation/` — `Experiment` с
  `impl_src_path`: те самые файлы, в которых утверждение реализовано,
  плюс `correspondence_percent` и `missing`.

## Что кладут в `data/paper_graphs/`

Каталог задаётся `settings.paper_graphs_dir`. Один элемент — одна
публикация, имя = **OpenAlex work id** (`W7164652155`): по этому ключу
карта индексирует публикации, иначе граф не с чем связать. Два варианта:

```
<publication_id>/                 экспорт OSA
    claims.json | claims_legacy.json   обязателен
    sections.json                      необязателен
    document.md                        необязателен: если нет sections.json,
                                       разделы разбираются из его заголовков
    experiments.json                   необязателен: claim → файлы
    layout.json | report.json |        необязателен: разобранная вёрстка PDF,
    elements.json                      по ней находится страница и блок, где
                                       стоит предложение-цитата
    graph.json                         необязателен: граф документа, по нему
                                       добавляются рисунки и таблицы, на
                                       которые этот блок ссылается
    meta.json                          необязателен: title, repository_url,
                                       publication_id (перебивает имя папки)
<publication_id>.json             готовый PaperGraph, как его пишет модель
```

Разбитый экспорт логируется и пропускается — один плохой каталог не должен
стоить карте всех остальных статей.

## Как склеиваются строки

- **claim → раздел.** По `section_id`, если такой раздел есть. OSA в
  экспорте `section_id` не пишет, поэтому фолбэк — по имени раздела
  (`section_name`, затем `section_heading_raw`), нормализованному по
  регистру и пробелам. Не нашлось — claim попадает в псевдораздел «вне
  разделов», а не выбрасывается.
- **id разделов** восстанавливаются из порядка (`s001`, `s002`, …) — тем
  же счётом, что в OSA, поэтому имена и номера сходятся.
- **claim → файлы.** `Experiment.description_from_paper` сравнивается с
  текстом claim и с его `original_text`; совпало — файлы, проценты и
  `missing` ложатся на этот claim. Не совпало — эксперимент становится
  отдельным claim без раздела: он единственный носитель ссылок на файлы,
  терять его нельзя.
- **URL файла** строится только для GitHub-репозитория:
  `<repo>/blob/HEAD/<path>`, из пути срезается префикс локального клона и
  суффикс `:<строка>` (он превращается в `#L<строка>`). Для остальных
  хостов URL не выдумывается — путь показывается текстом.
- **Разделы, из которых ничего не извлекли, в граф не идут** — иначе от
  публикации веером расходились бы пустые узлы.
- **claim → источники.** Всегда есть узел-цитата: `original_text`, то самое
  предложение, на котором утверждение держится. Если в экспорте лежит
  вёрстка, к нему добавляется блок страницы: цитата ищется подстрокой по
  нормализованному тексту элементов (одинаково схлопнутые пробелы и
  регистр — в `claims.json` текст пришёл из Markdown, в вёрстке из
  layout-прохода, слова те же, переносы разные), при неудаче — по первым
  80 символам, чтобы пережить абзац, разорванный на два элемента. Дальше
  по рёбрам `text_references` из `graph.json` добавляются рисунки и
  таблицы, на которые блок ссылается (до трёх), с подписью из
  `caption_of`. Номера страниц приводятся к 1-based: OSA считает с нуля,
  читатель — с единицы.
- **Окрестность в графе документа.** Из `graph.json` в `PaperGraph.document`
  берутся элементы не дальше `DOC_HOPS = 2` рёбер от любого узла-источника
  (блок страницы, рисунок) и рёбра между ними — только `reading_order`,
  `section_member`, `caption_of`, `text_references`; страницы и
  `page_contains`/`next_page` о связи двух элементов ничего не говорят.
  Весь документ не берётся: все статьи едут в карту одним файлом. Текст
  элемента — из `graph.json`, иначе из вёрстки, иначе `description`,
  обрезается до `DOC_TEXT_CHARS = 400`.

## Генерация файла карты

```bash
uv run python -m pauk.gui.generate_paper_graphs [--src data/paper_graphs] [--public]
```

Пишет `paper-graphs.js` (`window.PAPER_GRAPHS`, ключ — id публикации) в
каталог сборки карты; `rebuild_map` делает то же самое четвёртым шагом
после снепшота, данных и статистики. Файл пишется всегда, даже пустой:
страница грузит его обычным `<script>`, и пустой объект лучше, чем 404.
В `REQUIRED_FILES` в `serve.py` его нет — установка без экспортов OSA
это нормальная установка.

## Что рисует фронт

`pauk/gui/web/paper-graph.js`, карточка «Граф статьи» в профиле публикации
(вкладка «Поиск»). Колонки слева направо: публикация → разделы →
утверждения → файлы, связи — кривые Безье, зум/панорама через `d3.zoom`.
Цвет рамки утверждения — категория claim, пунктирная рамка — «код не
сопоставлен». Клик по утверждению открывает под графом цитату из статьи
(`original_text`), процент соответствия, чего не нашли в коде, и ссылки на
файлы. Кнопка «только с кодом» перерисовывает граф без утверждений без
файлов. Кнопка «источники» (включена по умолчанию) подвешивает под
выбранное утверждение узлы, откуда оно извлечено — цитата, блок страницы,
рисунки по ссылкам в тексте. Показываются только для выбранного: все
разом похоронили бы карту статьи под собственными доказательствами.
Узел-источник, который есть в графе документа (`doc` в
`paper-graphs.js`), помечен ▸: клик раскрывает под ним соседей по графу
документа — заголовок раздела, соседние блоки по порядку чтения, подпись,
рисунок, члены раздела — с подписью, как сосед связан с узлом выше, и
счётчиком других утверждений, извлечённых из того же элемента. Соседи
раскрываются дальше тем же кликом, обратно вверх по пути не ведут; больше
`PG_DOC_MAX = 10` соседей не рисуется, остальное — счётчик. Свернуть узел —
свернуть всё, что под ним; выбор другого утверждения сворачивает всё.
Перерисовка после клика сохраняет текущий зум и, если раскрытые источники
ушли за нижний край, подвигает вид ровно настолько, чтобы утверждение
осталось видно. На карточке публикации на самой карте (`tab-pubs.js`) — строка со
счётчиками.
