# `pauk/gui/` — карта

**Что здесь:** как снепшот графа превращается в раскладку и JSON для сайта,
и как устроен сам сайт.

**Какие файлы задействует:** `pauk/gui/graph_builder.py`, `authorship.py`,
`departments.py`, `layout.py`, `nodes.py`, `edges.py`, `config.py`,
`pauk/gui/web/`.

Neo4j напрямую трогает только `pauk/cache/export.py` — `pauk/gui/`
читает готовый снепшот с диска, не базу (см. [cache.md](cache.md)).

## `graph_builder.py` — снепшот → раскладка → JSON

```bash
uv run python -m pauk.gui.graph_builder --cache data/cache/graph_snapshot_<дата>.json [--out-dir ...] [--seed 42]
```

По умолчанию пишет в `data/gui/` (`pauk.settings.Settings.gui_dir`):

- `graph-data.json` — summary для карты: таблица департаментов, узлы
  (`key`/`kind`/`dept`/`label`/`rank`/`gx`/`gy` + одно сводное число),
  все рёбра;
- `authors-detail.json`, `repos-detail.json`, `pubs-detail.json` —
  расширенные поля, сайт догружает их лениво, после карты.

Приватность решается папкой, не содержимым: `authors-detail.json` (личные
поля) пишется только в `private/`, остальные три — и в `public/`, и в
`private/` (Vite раздаёт статику из одной папки). Стадии — по модулю на
каждую: `authorship.py` (кто что написал), `departments.py`,
`layout.py`, `nodes.py`, `edges.py`.

**Внешние авторы.** Экспорт берёт всех `Person` (с полем `is_itmo`) и всё
`AUTHORED`. На карту попадают публикации хотя бы с одним ИТМО-автором и все
их авторы, внешние соавторы — наравне с ИТМО: та же раскладка, то же правило
департамента, та же статистика. Отличие одно — `is_itmo: false` на узле, по
которому сайт прячет их фильтром "Показывать внешних авторов" (по умолчанию
выключен). Внешний, у которого нет ни одной ИТМО-публикации, в граф не
попадает. У статьи-коллаборации больше `hyperauthor_pub_size` авторов
(`config.py`, до ~1700 в реальных данных) рёбра соавторства строятся только
от ИТМО-авторов, а не каждый с каждым — иначе миллионы пар. Снепшот без
`is_itmo` (экспорт до внешних авторов) читается как "все из ИТМО".

**Раскладка департаментов (`departments.py`):**
- публикация — большинство голосов среди её авторов (голосуют только
  ИТМО-авторы: связь `BELONGS_TO` есть только у них; полный список
  в `depts`, один основной в `dept` для цвета);
- автор — департамент его самой свежей публикации;
- репозиторий — большинство по департаментам публикаций, которые он
  реализует.

Ничьи разрешаются по id, намеренно не по глобальной популярности — иначе
крупные департаменты подтягивали бы к себе всё спорное и росли бы сами от
себя (rich-get-richer).

**FA2-раскладка (`fa2_blended_layout` в `layout.py`)**: три отдельных
прогона ForceAtlas2 — по одному на авторов/публикации/репозитории,
каждый со своей мерой близости (авторы: совместные публикации + репозитории
+ разреженные "тот же департамент"-рёбра; публикации: общие авторы, top-K
сильнейших связей на публикацию; репозитории: общие публикации). FA2
считается только на гигантской связной компоненте — несвязанные компоненты
при полном графе только отталкиваются друг от друга без предела и после
масштабирования всё содержимое схлопывается в точку в центре. Всё остальное
(маленькие компоненты, синглтоны) домешивается после отдельным проходом с
джиттером на грубой occupancy-сетке. Финальный проход `spread_min_distance`
(через `scipy.spatial.cKDTree`) разводит узлы ближе минимальной дистанции.
Раскладку стоит проверять визуально — метрики не отражают качество
итогового расположения.

ForceAtlas2 — `fa2_modified` с приближением Barnes-Hut (`layout.py::fa2_layout`),
не `networkx.forceatlas2_layout`: тот строит плотную матрицу расстояний
n×n на каждой итерации (O(n²) по времени и памяти) и на ~15 тыс. узлов не
влезает в 16 ГБ. На реальном графе авторов Barnes-Hut в ~10 раз быстрее
(36 с против 379 с), а по сплочённости департаментов и длине рёбер
соавторства результат не отличается от точного сильнее, чем два запуска
точного с разными seed. Детерминирован: стартовые позиции из `seed`, другой
случайности в алгоритме нет.

Число итераций FA2/пороги рёбер — в `config.py`; константы, нужные ровно
одной функции (`COORD_MIN`/`COORD_MAX`, `STRANDED_JITTER`/
`STRANDED_MIN_SEP`), — прямо в `layout.py`.

## `pauk/gui/web/` — сайт

TypeScript + Vite, карта на Sigma.js (graphology). `vite.config.ts::publicDir`
указывает на `data/gui/private/`, так что данные подхватываются и в
`npm run dev`, и в сборке.

```bash
cd pauk/gui/web
npm install
npm run dev        # локально
npm run build      # dist/ — статика вместе с данными
npm test && npm run typecheck && npm run lint
```

Слои `src/` (порядок импорта проверяет eslint-boundaries — слой импортирует
только из себя и нижних): `contracts` (формы JSON, зеркало генератора) →
`core` (состояние `Store`, конфиг, i18n, загрузка данных) → `map`
(наполнение графа, регионы департаментов) → `features` (вкладки, панель,
фильтры, поиск, выбор) → `app` (точка входа).

Три вкладки: Авторы, Публикации, Репозитории, плюс глобальный поиск по всем
видам сразу. Вкладки "Здоровье БД" нет — проверки графа живут в админ-панели.

Деплой на лабораторный сервер — [deploy.md](deploy.md).
