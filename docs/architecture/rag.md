# RAG по графу (`pauk/rag`)

**Что здесь:** поиск экспертов по свободному вопросу через векторный и
полнотекстовый поиск в Neo4j, сборка экспертов по связям графа, ответ LLM
со ссылками на найденное; построение индексов профилями и валидация с
абляциями.

**Какие файлы задействует:** `pauk/rag/*.py`, `pauk/sources/github.py`
(`get_readme`), `pauk/urls.py` (`github_owner_name`); на диске —
`data/rag/` (кэш README, кэш векторов, манифесты профилей, прогоны валидации;
каталог в `.gitignore`).

## Поток

```
вопрос (как есть, без разбора LLM)
  │ embedder.encode / escape_lucene
Neo4j: vector index + full-text index профиля   retrieve: dense | bm25 | hybrid
  │ топ-k публикаций и репозиториев с баллами
Neo4j: AUTHORED, CONTRIBUTED_TO                  experts: Σ relevance² по работам человека
  │
LLM                                              answer: текст с [n] только на найденные источники
```

Вопрос не переписывается моделью; единственное исключение — для BM25 он
переводится в английские ключевые слова (`translate`, по умолчанию включён в
`ask` и CLI, см. результаты ниже; при сбое LLM поиск идёт по вопросу как есть
с заметкой в `notes`). Разбор вопроса и фильтры добавляются и меряются отдельно.

## Профили индекса (`profiles.py`)

Профиль — какие поля узла образуют встраиваемый текст. Единица абляции:
два профиля, различающиеся одним полем, строятся рядом и сравниваются на
одних вопросах.

| Узел | Поля |
|---|---|
| `Publication` | `title`, `abstract`, `fields` (домены OpenAlex), `journal`, `full_text` (первые 2000 символов) |
| `Repository` | `name`, `description`, `readme` (очищенное начало, ≥20 слов), `readme_raw` (как отдаёт GitHub), `implemented` (названия реализуемых статей) |

Пресеты: `full` (обоснованный выбор) и варианты, меняющие в нём ровно одно —
`no_readme`, `raw_readme`, `no_implemented`, `with_fields`, `with_full_text`,
плюс нижняя граница `title_only`. Произвольный профиль — через
`--publication-fields` / `--repository-fields`.

Почему такой `full` (по данным на 2026-10-06): аннотация есть у 81% статей
(медиана 1030 символов — целиком входит в окно модели); у репозиториев
описание короткое (медиана 65 символов), `topics` в графе нет вовсе, README
есть у 384 из 409 и почти всегда информативнее описания; 14 репозиториев без
описания и README, 11 из них реализуют статью — их находят только по
`implemented`. Записи типов `paratext`, `peer-review` и рисунки без аннотации
(`other`, `dataset`) не индексируются: короткая подпись вроде «Graphical
Abstract» близка к любому расплывчатому вопросу.

## Хранение в Neo4j (`graph.py`, `index.py`)

На узел профиля `p` и модели `m`: `rag_text_p` (собранный текст, общий для
всех моделей), `rag_vec_p_m` (float32, через `db.create.setNodeVectorProperty`),
`rag_hash_p_m` (sha1 модели и текста). Индексы: `rag_vec_p_m_<label>`
(векторный, cosine, свой у каждой модели) и `rag_text_p_<label>`
(полнотекстовый Lucene, один на профиль — BM25 от модели не зависит; ранжирование BM25, анализатор
`english`: стоп-слова и стемминг английского; русский вопрос к нему идёт через
перевод, см. `translate`).

- `pauk publish` пишет узлы через `SET n += ...` и `rag_*` не трогает. Если у
  узла изменился текст, его хэш перестаёт совпадать, и следующий `pauk rag
  index` пересчитает только его.
- Векторы кэшируются на диске по хэшу текста (`data/rag/vectors/`): профили с
  одинаковыми полями статей не встраивают 13 тысяч аннотаций заново.
- `pauk rag drop --profile p` удаляет свойства и индексы профиля целиком,
  `--model m` — только векторы одной модели. Манифест — `data/rag/profiles/p@m.json`.
- `queryNodes` векторного индекса возвращает cosine, приведённый к [0, 1] как
  (1 + cos) / 2 (и `SEARCH`, которым он запрашивается, тоже); для ранжирования это не важно, для чтения сырых баллов — да.

## Режимы поиска (`retrieve.py`)

- `dense` — векторный индекс; находит по смыслу, в том числе русский вопрос
  к английской аннотации.
- `bm25` — полнотекстовый индекс по словам вопроса (операторы Lucene
  экранируются: `RT-DETR` — не «RT без DETR»). Русский вопрос к английскому
  тексту совпадает только по названиям и числам — это ожидаемое ограничение
  режима, а не ошибка.
- `hybrid` — обе выдачи на глубину 2k, каждая min-max нормируется,
  0.7·dense + 0.3·bm25; `--fusion rrf` — reciprocal rank fusion по рангам.

Эксперты (`Rag.experts`): балл человека — сумма по его найденным работам
(релевантность, нормированная внутри типа)²; репозиторий весит 0.5 статьи.
Квадрат — чтобы одна точная работа перевешивала несколько смежных.

## Валидация (`evaluation.py`)

Вариант — `профиль:режим[:fusion]`. Все варианты отвечают на все вопросы;
топ-k людей, публикаций и репозиториев объединяются в пул (TREC-пулинг),
размечается только пул (0/1/2). Вопрос без единого релевантного элемента
некоторого типа в метрики этого типа не входит. Cutoff'ы задаются `--k`
(по умолчанию 5 и k пула) и не могут превышать k, с которым собран пул: глубже
нет ни выдачи, ни оценок. Recall@k — пуловый: в знаменателе релевантные
элементы, найденные хоть одним вариантом, а не все релевантные в графе, поэтому
он завышен и годится для сравнения вариантов, а не для оценки полноты. `compute_metrics` даёт P@5,
P@k, nDCG@k, MRR, judged@k по типу и варианту, а с `--baseline` — знаковый
тест по вопросам (wins, losses, двусторонний p). Оценки прототипа
(`data/search/*/judgments*.json`) переносятся через `--seed-judgments`:
ключи — текст вопроса и id узла.

## Команды

```bash
uv run pauk rag readmes --seed data/search/readmes       # кэш README (сеть только для недостающих)
uv run pauk rag index --profile full                     # построить / обновить профиль
uv run pauk rag index --profile no_readme
uv run pauk rag index --profile full --model qwen3       # тот же профиль, векторы другой модели рядом
uv run pauk rag profiles                                 # пресеты, поля, что построено
uv run pauk rag ask "кто занимается федеративным обучением" --no-answer   # qwen3, ключевые слова в BM25 и в эмбеддер; --no-dense-keywords, --no-keywords
uv run pauk rag pool --run validation --variants full:hybrid:en,full:dense,no_readme:hybrid:en
uv run pauk rag pool --run validation                    # без --variants: те же варианты, что уже в пуле
uv run pauk rag metrics --run validation --judge claude --baseline full:hybrid:en
uv run pauk rag metrics --run validation --judge claude --k 3,5,10   # свои cutoff'ы, не больше k пула
uv run pauk rag drop --profile no_readme
```

## Модели эмбеддингов (`models.py`)

`--model` у `index`, `ask` и `drop`; по умолчанию — `PAUK_RAG_EMBEDDING_MODEL`
(`Qwen/Qwen3-Embedding-0.6B`, с 2026-10-15). В валидации модель — часть
варианта: `full@qwen3:dense`; вариант без `@` — всегда bge-m3, а не модель по
умолчанию, чтобы размеченные варианты не меняли смысл при смене умолчания. `Rag.profile` не даёт искать векторами модели,
которой профиль не собран: вопрос и документы должны быть встроены одной
моделью, иначе поиск молча вернёт шум.

| alias | модель | параметры | префикс вопроса |
|---|---|---|---|
| `bge` | `BAAI/bge-m3` | 568M, 1024 | — |
| `arctic` | `Snowflake/snowflake-arctic-embed-l-v2.0` | 568M, 1024 | `query: ` |
| `qwen3` | `Qwen/Qwen3-Embedding-0.6B` | 600M, 1024 | `Instruct: <задача>\nQuery:` |

`arctic` — та же основа XLM-R large, что у bge-m3; `qwen3` — эмбеддинги на
основе LLM. Инструктивные модели обучены с задачей перед вопросом (документы —
без префикса); без неё они заметно проседают.

`intfloat/multilingual-e5-large-instruct` проверялась и исключена (2026-10-14):
nDCG@10 по людям 0.20 против 0.65 у bge-m3 в режиме dense, проигрыш на 22 из 23
вопросов. Модель тянется к языку вопроса: на «Кто занимается федеративным
обучением?» наверху русские тексты про обучение в смысле образования, а не
английские статьи про federated learning; инструкция перед вопросом этого не
исправляет.

Зависимость — extra `rag` (`sentence-transformers`).

## Результаты валидации (2026-10-07)

Прогон `data/rag/runs/validation`: 34 вопроса (24 тематических — люди и
публикации, 10 про код — репозитории), пул из 11 вариантов, 1604 оценки
одного оценщика (LLM), согласие с человеком ещё не измерено. nDCG@10 и
знаковый тест по вопросам:

| | люди | публикации | репозитории |
|---|---|---|---|
| `full:bm25` (вопрос по-русски) | 0.087 | 0.070 | 0.114 |
| `full:bm25:en` (перевод) | 0.692 | 0.619 | 0.814 |
| `full:dense` | 0.656 | 0.609 | 0.766 |
| `full:hybrid` | 0.619 | 0.591 | 0.732 |
| **`full:hybrid:en`** | **0.741** | **0.698** | **0.854** |

- `hybrid:en` лучше `hybrid` везде: 15:3 (p = 0.008), 18:4 (p = 0.004), 8:1 (p = 0.04).
- Без перевода BM25 бесполезен и тянет `hybrid` ниже `dense`.
- README (репозитории, `hybrid:en`): без него nDCG 0.753 против 0.854,
  0:10, p = 0.002. Очистка README на `hybrid:en` разницы не дала (4:4), на
  `hybrid` без перевода — дала (сырой хуже, 1:8, p = 0.04).
- Ограничения: один оценщик; 10 вопросов про код; тексты статей и README —
  только начало (окно 512 токенов).

## Сравнение моделей (2026-10-14)

Тот же прогон, пул расширен вариантами arctic и Qwen3 (9 вариантов, все
элементы топ-10 размечены, оценщик тот же). Новые модели нашли релевантные
документы, которых в пуле не было, поэтому идеальный порядок для nDCG вырос, и
цифры bge-m3 ниже, чем в таблице 2026-10-07; сравнимы только цифры одного
прогона. nDCG@10:

| модель | вариант | люди | публикации | репозитории |
|---|---|---|---|---|
| bge-m3 | dense | 0.646 | 0.544 | 0.739 |
| | hybrid:en | 0.731 | 0.628 | 0.824 |
| arctic-embed-l-v2.0 | dense | 0.588 | 0.578 | 0.804 |
| | hybrid:en | 0.689 | 0.642 | 0.898 |
| Qwen3-Embedding-0.6B | dense | 0.676 | 0.600 | 0.853 |
| | **hybrid:en** | **0.734** | **0.662** | **0.907** |

- Qwen3 лучшая во всех трёх типах, но отрыв от bge-m3 (`hybrid:en`) не
  значим: 14:9, 14:10, 7:2 (p = 0.40, 0.54, 0.18).
- Перевод для BM25 помогает каждой модели.
- Модели проваливаются на разных вопросах: «диффузионные модели» — Qwen3 0.00,
  bge-m3 0.92; AutoML — Qwen3 0.74, bge-m3 0.12. Следующий шаг — слияние выдач
  двух моделей.
- Публикации: часть потерь — потолок метрики (у многих вопросов меньше 10
  релевантных статей; максимально достижимый P@10 в среднем 0.84) и вопросы с
  ограничениями (годы, подразделение), которые RAG не применяет как фильтры;
  у 19% статей нет аннотации — в индексе только название.
