# `pauk/storage/` — чтение и запись JSONL

**Что здесь:** файловый слой prepared/raw-данных — чтение, атомарная
запись, межпроцессные блокировки, статический справочник департаментов.

**Какие файлы задействует:** `pauk/storage/raw.py`, `prepared.py`,
`atomic.py`, `naming.py`, `static.py`.

Ничего, кроме файлового ввода-вывода. Не знает про модели предметной
области (кроме `static.py`, который знает `Department` напрямую).

## `raw.py::RawStore`

Append-only хранилище сырых ответов внешних API,
`data/raw/<group>/<source>.jsonl`. `append(source, payload, request)`
пишет одну строку (`source`, `fetched_at`, `request`, `payload`),
`fsync()` на каждую — так что оборванный процесс теряет максимум
последнюю незаписанную строку, не файл целиком. `read(source)` разбирает
JSONL построчно; если последняя строка не парсится (обрыв записи
посреди работы) — не падает, логирует warning и просто её пропускает.

## `prepared.py::PreparedStore`

Шесть сущностей, `FILES = {"publications": "publications.jsonl", ...}`.
`read_models(entity, ModelClass)` — генератор pydantic-объектов,
`write_models(entity, rows)` — перезаписывает файл целиком через
`AtomicWriter`, сериализуя `model_dump_json(by_alias=True,
exclude_none=True)` на строку. `read_rows`/`write_rows` — то же самое, но
на голых dict, без модели (используется там, где строгая pydantic-схема
не нужна или ещё не готова).

`entity_for_path(path)` — обратное отображение путь → имя сущности,
использует `pauk/cli.py` для `enrich --input <файл>` (точечный запуск
этапа на конкретном файле вместо целой группы).

## `atomic.py`

- **`AtomicWriter`** — пишет во временный файл рядом с целевым
  (`.{имя}.{суффикс}.tmp`), заменяет целевой через `os.replace()` только
  после успешного закрытия. Значит либо старый файл цел, либо новый
  полностью записан — никогда не половина одного, половина другого, даже
  если процесс упадёт посреди записи.
- **`GroupLock`** — межпроцессная блокировка на одну группу
  (`data/.locks/<group>.lock`), PID-файл. Если владелец лока мёртв
  (`os.kill(pid, 0)` кидает `ProcessLookupError`) — лок считается
  протухшим и снимается сам. Используется `collect`/`normalize`/`enrich`
  — предохраняет от двух параллельных прогонов на одной группе, которые
  бы гонялись за одними и теми же файлами.

## `naming.py`

- **`group_name(work_id=..., date_from=..., date_to=..., name=...)`** —
  генерирует имя группы; явный `name` побеждает, иначе `<сегодня>__<work_id>`
  или `<сегодня>__from_<start>__to_<end>`.
- **`validate_group(group)`** — регекс `^[A-Za-z0-9][A-Za-z0-9_.-]*$`,
  защита от path traversal через имя группы (группа становится частью
  пути на диске).

## `static.py::StaticStore`

Каталог департаментов. Сначала пробует `data/static/departments.jsonl`
(если кто-то уже сгенерировал сущности напрямую); если файла нет — падает
на `data/static/departments_catalog.json`, версионируемый исторический
справочник ИТМО, и строит `Department` из него на лету. id — детерминированный
`sha256(name_en.casefold())[:12]` с префиксом `dept_` — стабилен между
прогонами без базы данных, которая бы иначе выдавала id.
