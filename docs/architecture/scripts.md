# Скрипты в `scripts/`

**Что здесь:** указатель по разовым и вспомогательным утилитам — что делает
каждая, когда она нужна и пишет ли она куда-нибудь. Подробности живут в
докстроках самих скриптов, здесь их нет.

**Какие файлы задействует:** весь каталог `scripts/`.

Общее правило: скрипт — это то, что не влезло в пайплайн, потому что требует
человеческого решения (курируемый список), закрывает дыру в стадии
(репозиторий, до которого она не дотягивается) или чинит уже записанное
(ремонт после багфикса). Регулярную работу делает `pauk` из `pauk/cli.py`,
а не эти файлы.

Колонка «пишет» — единственное, что важно знать до запуска.

## Эксплуатация сервера

| Скрипт | Что делает | Пишет |
|---|---|---|
| `deploy.sh` | `git pull` на сервере и перезапуск `screen`-сессии раздачи. Карту заново **не** генерирует | сервер |
| `mongo-up.sh` | Идемпотентный (пере)запуск контейнера `pauk-mongo` на сервере | сервер |
| `snapshot_mongo.py` | Выгрузка prepared-коллекций в Extended JSON, по файлу на коллекцию, с манифестом и sha256 | нет, только читает |

`snapshot_mongo.py` — точка отката. Снимать его перед любой операцией,
которая перезаписывает prepared-данные; он же готовит вход для стенда.

## Стенд для репетиции

| Скрипт | Что делает | Пишет |
|---|---|---|
| `rehearsal_up.sh` | Поднимает одноразовую копию боевого окружения: Neo4j из дампа, Mongo из снимков `snapshot_mongo.py` | локальный docker |
| `rehearsal_down.sh` | Убирает контейнеры стенда и том с восстановленным графом | локальный docker |

Запускать из обычного терминала: нужна принадлежность к группе `docker`,
которой у процесса, стартовавшего до `usermod -aG docker`, нет.

## Ручное пополнение данных

| Скрипт | Что делает | Пишет |
|---|---|---|
| `import_curated_repos.py` | Импорт списка `title,repo_url`, размеченного человеком, в `Repository.publication_ids` — то есть в `IMPLEMENTS`. Два шага: `plan` только читает и складывает решение в JSON, `apply` пишет ровно просмотренный план | `apply` — в Mongo |
| `verify_curated_repos.py` | Проверяет каждую строку исходного CSV по факту: есть ли узел репозитория, есть ли узел статьи, есть ли ребро между ними | нет |
| `resolve_missing_works.py` | Спрашивает у OpenAlex, какой работе соответствует заголовок, которого в графе нет; выдаёт список id для `pauk collect --works-file` | нет |
| `harvest_orphan_repos.py` | Собирает людей за репозиториями, до которых стадия `repositories` не дотягивается: она ходит по `repo_links`, а созданный импортом репозиторий ссылки на себя не имеет и не посещается даже с `--force` | Mongo |

`verify_curated_repos.py` намеренно не переиспользует матчинг из
`import_curated_repos.py`: проверяющий, разделяющий логику с проверяемым, не
поймает ошибку в этой логике.

Порядок для курируемого списка: `plan` → просмотр отчёта → `apply` →
`harvest_orphan_repos.py` → `pauk publish graph` → `verify_curated_repos.py`.

Самого списка в репозитории нет — он живёт у того, кто его ведёт, и путь к
нему передаётся флагом `--csv`. Дефолтное значение флага
(`itmo-github-repos.csv` в корне) рассчитано на этот файл рядом с чекаутом.

## Ремонт уже записанного

| Скрипт | Что делает | Пишет |
|---|---|---|
| `repair_implements.py` | Снимает притязания `IMPLEMENTS`, пришедшие из ссылок, признанных чужим инструментом. Багфикс останавливает появление новых, но `publication_ids` только растёт и сам не чистится | Mongo |
| `prune_stranger_profiles.py` | Удаляет GitHub-профили, добытые только с репозиториев, которые никто не реализует | Mongo |
| `prune_graph_to_mongo.py` | Удаляет из графа то, чего в Mongo больше нет: рёбра `IMPLEMENTS` и узлы `GitHubProfile` | Neo4j |

`prune_graph_to_mongo.py` — обход [#145](https://github.com/ITMO-NSS-team/PAUK/issues/145):
`publish graph` работает только на `MERGE` и не удаляет ничего, поэтому
витрина расходится с источником молча. Когда #145 починят, скрипт нужно
удалить, а не оставлять «на всякий случай».

## Каталоги и оценка качества

| Скрипт | Что делает | Пишет |
|---|---|---|
| `build_department_catalog.py` | Разовая генерация черновика справочника подразделений ИТМО со страницы структуры: факультеты → институты → центры → лаборатории | черновик в `data/static/` |
| `export_link_labels.py` | Выгружает ссылки (или целые статьи) в CSV под ручную разметку — единственная в репозитории оснастка для измерения точности и полноты извлечения ссылок | нет |
| `mass_launch_osa_tool.py` | Пакетный запуск внешнего `osa_tool` по списку репозиториев | внешний инструмент |

У `export_link_labels.py` два режима: `links` меряет точность по уже
извлечённым ссылкам, `papers` — полноту, которую по извлечённому множеству
увидеть нельзя. В режиме `papers` найденные PAUK ссылки по умолчанию скрыты:
показать их разметчику — значит превратить независимый поиск в подтверждение
и завысить полноту.
