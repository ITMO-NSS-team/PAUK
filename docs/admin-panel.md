# Админ-панель: запуск и устройство

Панель правит граф вручную — так, чтобы правка пережила следующий
`pauk publish graph`. Отдельный сервис на FastAPI, поднимается рядом с
базой; публичная карта (`pauk/gui/serve.py`) остаётся раздачей статики и
про запись ничего не знает.

## Что нужно для запуска

Две базы:

- **MongoDB** — учётные записи панели, сессии, журнал правок и сами
  решения о правках. Без неё панель не стартует.
- **Neo4j** — сам граф. Без него панель работает, но экраны узлов
  честно скажут «база графа не отвечает»; вход и учётные записи не
  зависят от Neo4j.

Настройки читаются из `.env` в корне репозитория — те же, что у
пайплайна:

```
MONGO_URI=mongodb://localhost:27017
MONGO_DB=pauk
NEO4J_URI=bolt://localhost:7687
NEO4J_USER=neo4j
NEO4J_PASSWORD=...
```

Отдельного пользователя Neo4j для панели нет: разделение прав живёт на
уровне приложения, а не базы (решение по инфраструктуре — отдельные
пользователи Neo4j доступны только в Enterprise).

## Запуск

Локальная MongoDB, если её нет:

```bash
docker run -d --name pauk-mongo -p 27017:27017 -v pauk-mongo-data:/data/db mongo:7
```

Завести себе учётную запись — пароль спросит промптом, в аргументах его
передавать нельзя:

```bash
uv run pauk admin user add andrey --role admin
```

Поднять панель:

```bash
uv run uvicorn pauk.admin.app:build --factory --port 8600
```

Открыть `http://127.0.0.1:8600`, войти под заведённым логином.

## Учётные записи

Аккаунт заводится только из терминала. В браузере нет ни регистрации, ни
восстановления пароля — маршрутов таких не существует.

```bash
uv run pauk admin user add ivanov --role editor   # создать
uv run pauk admin user list                        # посмотреть
uv run pauk admin user disable ivanov              # заблокировать
uv run pauk admin user enable ivanov               # вернуть
```

Три роли:

| роль | что может |
|---|---|
| `viewer` | только смотреть: поиск, карточка узла, связи |
| `editor` | плюс править поля, удалять узлы, связывать и отвязывать |
| `admin` | то же, что `editor` (пока различий нет, задел на будущее) |

Пароль хранится как `scrypt`-хеш со своей солью. При входе создаётся
строка сессии в MongoDB, в браузер уходит только случайный токен в куке
`HttpOnly`. Поэтому `disable` действует мгновенно: сессии удаляются
вместе с блокировкой, а не доживают до истечения куки.

Каждая правка пишется в журнал с именем автора — `user:ivanov`.

## Как это устроено внутри

Панель ничего не правит в графе напрямую. Все изменения идут через
`pauk/graph/mutations.py`, где закрытые списки: 7 меток, 11 типов связей
и поля, выведенные из `NODE_REGISTRY`. Ни метка, ни имя поля не могут
прийти из формы — они подставляются в Cypher, и произвольный запрос
невозможен.

Порядок у любой правки один: **сначала запись в граф, потом фиксация
решения**. Если граф правку отклонил, решения не остаётся — иначе
следующая публикация молча применила бы изменение, о котором человеку
только что сказали «отказано».

Правки переживают публикацию так:

- **изменение поля** — записывается в `graph_overrides` и применяется
  заново после каждого `publish` и каждого дедупа;
- **удаление узла** — оставляет пометку, иначе `MERGE` создаст узел
  заново на следующем прогоне;
- **удаление связи** — тоже оставляет пометку, по той же причине;
- **создание связи** — не записывается ничего, и это не упущение:
  загрузчик только добавляет связи, для которых у него есть строки, и
  никогда не удаляет те, о которых не знает. Связь, созданная руками,
  переживает публикацию сама.

Вместе с изменением поля сохраняется и то, что стояло там раньше — чтобы
позже было видно, если источник начал говорить другое.

## Тест на боевых данных

Панель добавляет в MongoDB четыре коллекции: `admin_users`,
`admin_sessions`, `graph_overrides`, `audit`. Пайплайн ими не
пользуется, так что подключиться к рабочей MongoDB безопасно — ничего
существующего панель не трогает.

С Neo4j иначе: **правка из панели уходит в настоящий граф сразу**.
Никакого «черновика» нет.

Поэтому для знакомства с панелью:

```bash
uv run pauk admin user add andrey --role viewer
```

С ролью `viewer` доступны поиск, карточки узлов и связи, а формы правки
не показываются — и на попытку отправить их всё равно придёт отказ.
Посмотреть данные можно на боевой базе, испортить их — нет.

Когда понадобится проверить именно правку, лучше поднять отдельный
Neo4j и указать его в `NEO4J_URI`, а не работать с рабочим графом.

## Что уже работает и чего ещё нет

Готово: вход, поиск по меткам, карточка узла со всеми полями и связями,
правка полей, удаление узла, создание и удаление связей.

Ещё не сделано: лента журнала правок с фильтрами, экран отката
одиночной правки и экран расхождений — где ручная правка разошлась с
тем, что теперь говорит источник. Всё это доступно из CLI
(`pauk admin overrides list|apply|undo`), но экранов пока нет.

## Если что-то не так

**«cannot reach MongoDB»** — база не запущена; команда печатает адрес и
пример команды запуска.

**«База графа не отвечает»** на экранах узлов — не задан
`NEO4J_PASSWORD` или Neo4j не поднят. Вход и учётные записи при этом
работают.

**Страница входа вместо нужной** — сессия истекла (12 часов) или
аккаунт заблокировали. После входа вернёт на ту страницу, куда шли.
